# VAM Knowledge Tree Generator

## 一、用户设定（可自行调整）

研究主题：{填入研究主题}

### 数量限制
- 最大标题数量：30（包含根标题）
- 最大层级深度：6（Markdown # 至 ######）

### 深度控制
- 层级模式：自然展开
- 最低研究深度：不限制
- 允许不同分支深度：是
- 允许不同分支的子节点数量：是

### 知识覆盖
- 知识完整性：优先
- 知识广度与深度：依主题复杂度动态分配
- 末端节点要求：可以独立研究

---

## 二、任务目标

请针对用户设定的研究主题，建立一份适合系统性知识探索与深入研究的 Markdown 层级式大纲。

目标不是制作传统的课程目录，而是建立一棵具有知识逻辑、深度不对称、能够逐层深入研究的知识树。

所有生成规则都必须遵守最上方的「用户设定」。

## 三、知识组织原则

1. 以知识体系的完整性、逻辑性与研究价值为优先。
2. 请以知识之间的依赖关系、因果关系与概念细分关系组织大纲，而不是依照教科书章节或课程顺序分类。
3. 大纲应是一棵非对称知识树，而不是平均分配的分类目录。
4. 依照每个知识领域的复杂程度，自然决定分支深度。
5. 不同分支可以有不同深度，也可以有不同数量的子节点。
6. 父节点代表知识领域、核心概念或作用机制；子节点代表更具体的原理、机制、因果关系或研究问题。
7. 每个子节点都必须与父节点存在明确的知识逻辑关系，而非仅仅属于相同主题。
8. 每个末端节点都必须具有独立研究价值，适合作为一个完整的研究单元。
9. 避免知识重复、过度拆分，以及没有实际研究价值的分类。

## 四、层级与深度规则

1. 使用 Markdown 标题表示知识层级。
2. 只使用一个 # 标题作为根主题。
3. 第一层子议题使用 ##，下一层使用 ###，依此类推。
4. 层级不得超过用户设定的最大深度。
5. 不要把所有分支固定在相同深度。
6. 简单概念可以停留在较浅层级。
7. 复杂概念应依其知识依赖关系继续深入。
8. 每一层都必须代表有意义的知识深化，而不是单纯增加标题。
9. 不要为了追求深度而创造不必要的中间节点。
10. 当某个概念值得进一步研究时，应优先沿着该分支深入，而不是持续增加同层分类。

## 五、知识关系与节点设计

优先呈现以下三种知识关系：

1. 概念细分：从抽象概念深入具体原理与机制。
2. 因果关系：从现象深入影响因素、作用机制与结果。
3. 依赖关系：从基础概念深入建立在其上的进阶知识。

节点设计要求：

1. 同一条知识路径应呈现逐步深化的研究逻辑。
2. 父节点应能合理统整其所有子节点。
3. 子节点应提供新的研究方向，而不是换句话说明父节点。
4. 末端节点应具有足够的具体性，可以进一步研究其原理、证据、限制与实际应用。
5. 避免只有分类功能、缺乏研究意义的节点。
6. 知识之间若存在跨领域关系，应选择最能解释其核心机制的位置，避免重复建立相同节点。
7. 不要为了填满层级而刻意增加没有研究价值的节点。

## 六、数量与完整性规则

1. 标题总数不得超过用户设定的最大标题数量。
2. 在数量限制内，优先涵盖最重要的核心知识领域。
3. 兼顾知识广度与必要的研究深度，不要为了追求广度而牺牲所有分支的深度。
4. 不要平均分配每个分类的标题数量。
5. 不必为了凑满标题数量而增加内容。
6. 优先保留具有高度研究价值、解释能力或知识依赖性的节点。
7. 不要使用固定的「每个大分类配置相同数量子议题」模式。
8. 如果数量限制与完整性发生冲突，应优先保留核心知识、关键依赖关系与最有价值的研究路径。

## 七、输出前的品质检查

在输出最终结果前，请自行检查：

1. 是否涵盖研究主题最重要的核心知识？
2. 是否具有明确的概念细分、因果或依赖关系？
3. 分支深度是否由知识复杂度决定，而非固定模板？
4. 是否存在值得深入却过早停止的分支？
5. 是否所有深入的节点都有实际知识价值？
6. 是否存在不必要的中间分类或重复节点？
7. 是否避免将知识树写成传统教科书目录？
8. 是否符合用户设定的数量与层级限制？

如果不符合，请先自行调整结构，再输出最终结果。

## 八、输出格式

1. 只输出 Markdown 标题。
2. 使用 # 至用户设定的最大层级深度。
3. 不使用粗体、清单、表格或任何补充说明。
4. 不要解释设计逻辑。
5. 不要输出品质检查结果。
6. 不要使用 Markdown 代码区块包住结果。
7. 只输出最终大纲本身。
