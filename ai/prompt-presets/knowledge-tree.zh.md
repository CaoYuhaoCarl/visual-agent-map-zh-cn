# VAM Knowledge Tree Generator

## 一、使用者設定（可自行調整）

研究主題：{填入研究主題}

### 數量限制
- 最大標題數量：30（包含根標題）
- 最大階層深度：6（Markdown # 至 ######）

### 深度控制
- 階層模式：自然展開
- 最低研究深度：不限制
- 允許不同分支深度：是
- 允許不同分支的子節點數量：是

### 知識覆蓋
- 知識完整性：優先
- 知識廣度與深度：依主題複雜度動態分配
- 末端節點要求：可以獨立研究

---

## 二、任務目標

請針對使用者設定的研究主題，建立一份適合系統性知識探索與深入研究的 Markdown 階層式大綱。

目標不是製作傳統的課程目錄，而是建立一棵具有知識邏輯、深度不對稱、能夠逐層深入研究的知識樹。

所有生成規則都必須遵守最上方的「使用者設定」。

## 三、知識組織原則

1. 以知識體系的完整性、邏輯性與研究價值為優先。
2. 請以知識之間的依賴關係、因果關係與概念細分關係組織大綱，而不是依照教科書章節或課程順序分類。
3. 大綱應是一棵非對稱知識樹，而不是平均分配的分類目錄。
4. 依照每個知識領域的複雜程度，自然決定分支深度。
5. 不同分支可以有不同深度，也可以有不同數量的子節點。
6. 父節點代表知識領域、核心概念或作用機制；子節點代表更具體的原理、機制、因果關係或研究問題。
7. 每個子節點都必須與父節點存在明確的知識邏輯關係，而非僅僅屬於相同主題。
8. 每個末端節點都必須具有獨立研究價值，適合作為一個完整的研究單元。
9. 避免知識重複、過度拆分，以及沒有實際研究價值的分類。

## 四、階層與深度規則

1. 使用 Markdown 標題表示知識階層。
2. 只使用一個 # 標題作為根主題。
3. 第一層子議題使用 ##，下一層使用 ###，依此類推。
4. 階層不得超過使用者設定的最大深度。
5. 不要把所有分支固定在相同深度。
6. 簡單概念可以停留在較淺層級。
7. 複雜概念應依其知識依賴關係繼續深入。
8. 每一層都必須代表有意義的知識深化，而不是單純增加標題。
9. 不要為了追求深度而創造不必要的中間節點。
10. 當某個概念值得進一步研究時，應優先沿著該分支深入，而不是持續增加同層分類。

## 五、知識關係與節點設計

優先呈現以下三種知識關係：

1. 概念細分：從抽象概念深入具體原理與機制。
2. 因果關係：從現象深入影響因素、作用機制與結果。
3. 依賴關係：從基礎概念深入建立在其上的進階知識。

節點設計要求：

1. 同一條知識路徑應呈現逐步深化的研究邏輯。
2. 父節點應能合理統整其所有子節點。
3. 子節點應提供新的研究方向，而不是換句話說明父節點。
4. 末端節點應具有足夠的具體性，可以進一步研究其原理、證據、限制與實際應用。
5. 避免只有分類功能、缺乏研究意義的節點。
6. 知識之間若存在跨領域關係，應選擇最能解釋其核心機制的位置，避免重複建立相同節點。
7. 不要為了填滿階層而刻意增加沒有研究價值的節點。

## 六、數量與完整性規則

1. 標題總數不得超過使用者設定的最大標題數量。
2. 在數量限制內，優先涵蓋最重要的核心知識領域。
3. 兼顧知識廣度與必要的研究深度，不要為了追求廣度而犧牲所有分支的深度。
4. 不要平均分配每個分類的標題數量。
5. 不必為了湊滿標題數量而增加內容。
6. 優先保留具有高度研究價值、解釋能力或知識依賴性的節點。
7. 不要使用固定的「每個大分類配置相同數量子議題」模式。
8. 如果數量限制與完整性發生衝突，應優先保留核心知識、關鍵依賴關係與最有價值的研究路徑。

## 七、輸出前的品質檢查

在輸出最終結果前，請自行檢查：

1. 是否涵蓋研究主題最重要的核心知識？
2. 是否具有明確的概念細分、因果或依賴關係？
3. 分支深度是否由知識複雜度決定，而非固定模板？
4. 是否存在值得深入卻過早停止的分支？
5. 是否所有深入的節點都有實際知識價值？
6. 是否存在不必要的中間分類或重複節點？
7. 是否避免將知識樹寫成傳統教科書目錄？
8. 是否符合使用者設定的數量與階層限制？

如果不符合，請先自行調整結構，再輸出最終結果。

## 八、輸出格式

1. 只輸出 Markdown 標題。
2. 使用 # 至使用者設定的最大階層深度。
3. 不使用粗體、清單、表格或任何補充說明。
4. 不要解釋設計邏輯。
5. 不要輸出品質檢查結果。
6. 不要使用 Markdown 程式碼區塊包住結果。
7. 只輸出最終大綱本身。
